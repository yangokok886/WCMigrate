# XChat Transfer：iOS 微信聊天数据迁移工具规划书

> 文档用途：交给 Mac 上的 Codex / AI 编程助手，作为项目立项、技术验证、架构设计、UI 设计和后续开发的统一依据。  
> 规划日期：2026-11-12  
> 暂定项目名：XChat Transfer  
> 目标平台：iPhone / iOS 26 及以上  
> 编译环境：Xcode + iOS 26 SDK  
> 首选方向：原生 iOS App，优先验证 Objective-C / UIKit 与 SwiftUI 混合架构的可行性；UI 可使用 SwiftUI 实现原生 Liquid Glass。

---

## 1. 项目目标

开发一个专注于微信数据备份、检查、迁移和恢复的 iOS IPA 工具。它不是通用文件管理器，也不是简单复制几个数据库文件的脚本。

用户在同一台 iPhone 上可能安装：

- 官方微信；
- 一个或多个不同 Bundle ID 的微信多开版本；
- 定制版微信或重新签名的微信；
- 不同版本的微信实例。

工具应尽可能自动发现这些实例，展示清晰的应用身份信息，让用户选择来源实例和目标实例，再执行经过预检、备份、校验和可回滚的迁移流程。

### 1.1 主要使用场景

例如手机中有三个微信实例：

| 显示昵称 | 应用标识符（Bundle ID） | 角色 |
|---|---|---|
| 微信 | `com.tencent.xin`（示例，必须运行时读取） | 官方实例 |
| 微信工作版 | 运行时读取 | 多开实例 A |
| 微信备用版 | 运行时读取 | 多开实例 B |

用户选择：

- 来源：微信工作版
- 目标：微信备用版
- 操作：备份来源数据 → 检查兼容性 → 迁移可迁移数据 → 校验 → 用户启动目标微信验证

目标体验是尽量做到“一键迁移”，但只有通过技术验证的迁移类型才能显示为可执行。不能把“复制文件成功”显示成“聊天记录迁移成功”。

### 1.2 项目边界

本工具仅面向用户本人有权管理的设备、微信实例和数据。不得设计成读取他人设备、窃取其他用户数据、绕过账号验证或伪造身份的工具。

项目不承诺：
- 绕过微信账号登录、设备验证或风控；
- 将一个账号的登录态无条件转移给另一个实例；
- 解密无法合法取得密钥的数据库；
- 保证任意微信版本、任意定制包之间的数据库兼容；
- 修复签名证书被撤销、企业证书掉签或安装包无法启动的问题。

## 3. 可行性判断：先验证，再承诺

### 3.1 可以作为第一阶段目标的能力

- 识别已安装应用及可读取的应用元数据；
- 显示应用昵称、Bundle ID、版本、容器状态和数据大小；
- 对用户选择的应用数据做备份；
- 识别微信数据目录中的文件类型和数据库文件；
- 生成文件清单、大小、时间、哈希校验结果；
- 读取可访问的 SQLite 数据库副本并生成结构报告；
- 对备份执行完整性校验；
- 在确认目标应用已退出后，执行经过授权且兼容性检查通过的文件级恢复；
- 提供失败回滚、恢复记录和手动导出。

### 3.2 必须单独验证的能力

以下能力不得在没有实机证据时写成“已支持”：

- 不同 Bundle ID 的微信之间是否能直接使用同一份数据库；
- 数据库是否加密、密钥位于何处，以及目标实例是否有权使用该密钥；
- 微信是否会校验数据库、账号标识、设备标识或实例标识；
- 微信不同版本之间数据库 schema 是否兼容；
- 图片、视频、语音、文件的索引与资源目录是否能正确对应；
- 目标微信首次启动时是否会重建、覆盖或清理迁入的数据；
- iOS 26 各小版本上的容器访问稳定性；
- 重新签名、改 Bundle ID 或更换 App Group 后对数据识别和恢复的影响。

### 3.3 关键技术现实

**沙盒访问权限不等于微信数据可迁移。**

获得某个容器的文件访问能力，只代表工具能够在授权范围内读取或写入文件，不代表它能理解微信私有数据格式，也不代表目标微信接受这些文件。

**数据库文件不等于完整聊天记录。**

迁移对象可能包括数据库主文件、SQLite WAL/SHM、媒体资源、索引、配置、账号关联信息等。必须先分析真实样本和版本差异，不能凭文件名猜测。

**Keychain 不属于普通沙盒目录复制范围。**

AppsManager27 的说明也指出，Keychain 受系统权限和沙盒限制，不能因为复制 Documents / Library 就认为登录状态也会转移。不要把登录态迁移作为 MVP 的承诺。

**掉签与数据迁移是两个问题。**

证书被撤销可能导致应用无法启动；迁移工具只能在应用和数据访问条件允许时帮助备份、恢复。重新签名后的 Bundle ID、Team ID、App Group 或容器身份变化，都可能影响数据归属与兼容性。

## 4. 产品功能结构

建议底部采用四个主 Tab，避免把它做成复杂的文件管理器。

### 4.1 首页 / 迁移

首页突出两个实例卡片和迁移流程：

- 来源实例：提供数据的微信；
- 目标实例：接受数据、其选定目录将被替换的微信；
- 两者必须明确区分，界面始终显示名称和 Bundle ID，避免选错实例。

- 来源微信卡片；
- 中间交换方向图标；
- 目标微信卡片；
- “开始迁移”主按钮；
- 最近一次备份状态；
- 当前设备、iOS 版本、访问能力状态。

用户点选卡片后进入实例选择页。来源与目标不能是同一个实例。

### 4.2 微信实例

应用列表每行展示：

- 应用图标（系统允许读取时）；
- 显示名称；
- Bundle ID；
- 版本号 / Build；
- 数据大小；
- 最近修改时间；
- 容器访问状态；
- 是否已备份；
- 是否正在运行（只能在有可靠依据时显示，不能猜测）。

支持搜索、排序、筛选和下拉刷新。

应用详情页分区：

1. 基本信息；
2. 容器信息；
3. 数据目录概览；
4. 微信数据识别结果；
5. 备份历史；
6. 风险和兼容性状态。

若 iOS 26 无法取得真实图标，应使用统一占位图标，不能把占位图标误认为真实应用图标。

### 4.3 目录选择与备份中心

本项目不把 Documents + Library 写死为唯一迁移范围。**每次迁移由用户自行选择要从来源微信读取、并替换到目标微信的目录或子目录。**

目录选择器要求：

- 分别展示来源实例和目标实例的目录树；
- 支持选择 Documents、Library，也支持展开后选择其中的子目录；
- 允许多选目录；
- 展示目录路径、文件数、总大小、可读写状态；
- 对系统管理目录、不可访问目录、符号链接、特殊文件和不支持的文件类型给出明确说明；
- 默认不勾选任何目录，用户必须明确选择；
- 提供“来源选择”和“目标映射”预览，不能仅按目录名称盲目覆盖；
- 对无法安全映射的目录禁止执行，并说明原因；
- 不允许把来源路径直接当成目标路径，必须由迁移计划生成明确的映射关系。

目标数据处理采用**每次迁移前询问**：

- 每次执行迁移前，显示目标将被替换的目录清单；
- 询问用户是否先备份目标对应目录；
- 用户可选择“备份后继续”或“取消迁移”；
- 为避免不可逆数据丢失，正式版本不提供无备份直接覆盖选项；
- 用户取消备份或备份失败时，不得继续写入目标目录；
- 备份应只覆盖本次将被替换的目标目录，不要求无必要地备份整个目标沙盒。

备份中心功能：

- 新建备份；
- 备份列表；
- 备份详情；
- 校验备份；
- 导出 ZIP；
- 删除备份（必须二次确认）；
- 按迁移任务恢复目标目录；
- 查看备份对应的来源 / 目标 Bundle ID、目录映射和时间；
- 失败后按迁移日志回滚。

备份目录建议按应用实例和时间分层，例如：

```text
Backups/
  <bundle-id>/
    <backup-id>/
      manifest.json
      metadata.json
      payload/
      checksums.sha256
      logs/
```

`manifest.json` 应记录：

- 备份 ID；
- 来源 Bundle ID；
- 应用版本和 Build；
- iOS 版本；
- 设备型号（非唯一敏感标识）；
- 备份创建时间；
- 数据目录清单；
- 文件数量和总字节数；
- 文件哈希；
- 备份格式版本；
- 迁移能力检测结果；
- 是否包含不支持的文件或跳过项。

不得将账号密码、明文密钥或登录令牌写入 manifest 或日志。

### 4.4 数据分析

这是本工具区别于普通文件管理器的核心页面。

显示：

- 识别到的数据库文件数量；
- 数据库文件大小；
- SQLite 表和索引概况；
- WAL / SHM 是否存在；
- 媒体资源目录数量和大小；
- 图片、视频、语音、文件等资源数量（仅在可靠识别时显示）；
- 未识别文件数量；
- 数据完整性检测结果；
- 版本兼容性报告。

默认只对**副本**做只读分析。不得在微信运行时直接对原始数据库执行写入或结构修改。

### 4.5 设置与日志

- iOS / App 版本信息；
- 访问能力和 App Group 状态；
- 数据存储位置；
- 备份保留策略（默认不自动删除）；
- 日志导出；
- 免责声明；
- 开源许可证；
- 故障诊断。

## 5. 迁移流程设计

建议使用状态机管理迁移，不要把所有逻辑塞进一个按钮回调。

```text
选择来源实例
    ↓
选择目标实例
    ↓
读取实例元数据
    ↓
检查来源与目标容器访问能力
    ↓
确认微信均已退出（无法确认时停止或要求用户手动确认）
    ↓
创建来源备份
    ↓
对备份做哈希与结构校验
    ↓
分析微信数据与版本兼容性
    ↓
生成迁移预览
    ↓
用户明确确认
    ↓
备份目标当前数据
    ↓
执行已验证的数据迁移策略
    ↓
检查文件数量、大小、哈希和目录结构
    ↓
记录结果
    ↓
用户手动启动目标微信验证
    ↓
成功 / 失败回滚
```

### 5.1 目录选择与映射

迁移计划必须由用户选择的目录生成，而不是默认整包替换：

1. 用户选择来源微信实例；
2. 工具读取其可访问目录树；
3. 用户勾选要迁移的目录或子目录；
4. 用户选择目标微信实例；
5. 工具读取目标目录树，并提出可解释的默认映射建议；
6. 用户逐项确认来源目录对应的目标目录；
7. 工具检查路径权限、目录类型、空间和冲突；
8. 生成迁移预览，用户确认后才进入备份询问。

来源和目标目录不要求同名，但映射必须明确。默认只允许映射到经过验证、用户明确选中的目标目录；不得因为路径同名就自动认定数据兼容。

### 5.2 迁移预览必须展示

- 来源应用名称与 Bundle ID；
- 目标应用名称与 Bundle ID；
- 来源和目标版本；
- 用户选择的来源目录；
- 每个来源目录对应的目标目录；
- 目标目录当前是否存在内容；
- 预计迁移文件数；
- 预计迁移数据量；
- 预计跳过文件数；
- 不兼容项目；
- 是否可能需要重新登录；
- 是否可能无法恢复聊天数据库；
- 哪些目标目录内容将被替换；
- 用户是否已决定备份目标数据；
- 回滚备份是否已经准备好。

### 5.3 迁移前目标数据询问

每次迁移任务都必须重新询问，不能沿用上一次的选择：

- 对话框列出本次会被替换的全部目标目录；
- 展示预计备份容量和可用磁盘空间；
- 提供“备份目标目录并继续”和“取消”两个明确选项；
- 用户选择继续后，先备份目标对应目录，再校验备份；
- 只有目标备份校验成功，才允许开始替换；
- 目标目录不存在时记录该状态，不伪造备份；
- 若备份失败、空间不足或校验失败，终止迁移；
- 备份文件应与迁移任务 ID 绑定，方便恢复。

### 5.4 迁移策略分级

建议 UI 使用明确的能力等级：

| 等级 | 含义 | UI 状态 |
|---|---|---|
| A：完整验证 | 同版本、同类实例，实机验证数据库与资源恢复成功 | 可执行 |
| B：部分兼容 | 文件恢复可行，但部分数据或登录状态不能保证 | 警告后执行 |
| C：仅备份 | 能安全备份和分析，尚未证明目标可恢复 | 仅备份 |
| D：不支持 | 权限不足、文件不完整或版本不兼容 | 禁止迁移 |

只有 A / B 可以出现迁移操作入口。C 只能备份和分析，D 必须解释原因。

### 5.5 回滚原则

- 目标数据在迁移前必须先备份；
- 不允许直接覆盖而没有恢复点；
- 文件写入失败时停止后续步骤；
- 每个阶段写入事务日志；
- App 重启后能够识别未完成任务；
- 校验失败时不显示成功；
- 回滚失败必须保留所有备份并提示用户，不得自动删除恢复材料。

### 6.1 核心模型建议

`AppInstance`：

```swift
struct AppInstance: Identifiable, Codable {
    let id: String
    let displayName: String
    let bundleIdentifier: String
    let version: String?
    let build: String?
    let dataContainerPath: String?
    let dataSize: Int64?
    let lastModified: Date?
    let accessState: AccessState
    let iconState: IconState
}
```

`MigrationPlan`：

```swift
struct MigrationPlan: Codable {
    let id: UUID
    let sourceBundleID: String
    let targetBundleID: String
    let sourceVersion: String?
    let targetVersion: String?
    let strategy: MigrationStrategy
    let estimatedBytes: Int64
    let estimatedFileCount: Int
    let compatibilityLevel: CompatibilityLevel
    let warnings: [String]
}
```

`DirectorySelection` 与 `DirectoryMapping`：

```swift
struct DirectorySelection: Codable, Identifiable {
    let id: UUID
    let sourceRelativePath: String
    let sourceFileCount: Int
    let sourceByteCount: Int64
}

struct DirectoryMapping: Codable, Identifiable {
    let id: UUID
    let sourceRelativePath: String
    let targetRelativePath: String
    let replacementMode: ReplacementMode
}

enum ReplacementMode: String, Codable {
    case replaceSelectedDirectory
}
```

目录路径应保存为容器内相对路径，并在执行时重新解析、校验根目录和路径边界。禁止直接信任 UI 传入的绝对路径，避免路径穿越或误写容器外文件。

`MigrationState`：

```swift
enum MigrationState: String, Codable {
    case idle
    case discovering
    case backingUpSource
    case verifyingBackup
    case analyzing
    case backingUpTarget
    case restoring
    case verifyingRestore
    case completed
    case failed
    case rollingBack
    case rolledBack
}
```

以上是模型示意。正式实现时还需要补充错误类型、取消状态、进度和持久化恢复信息。

### 6.3 底层访问模块

把 AppsManager27 / WQFiles 涉及的容器访问能力封装为统一接口，例如：

```swift
protocol ContainerAccessProvider {
    func discoverApplications() async throws -> [AppInstance]
    func inspectContainer(for bundleID: String) async throws -> ContainerInfo
    func readMetadata(for bundleID: String) async throws -> AppMetadata
    func checkAccess() async -> AccessReport
}
```

注意：

- 这是架构接口，不代表 iOS 公共 API 天然允许访问任意第三方 App 沙盒；
- 具体实现必须依赖经过审查、合法授权且在目标系统版本上实测的能力；
- 不要把访问方法写死在 UI 或业务逻辑中；
- iOS 26 与 iOS 27 应使用独立适配层；
- 不支持的能力必须返回明确错误，不能静默返回空列表；
- 不要把容器 UUID 当成 Bundle ID；
- 不要把 App Group 容器误认为应用主数据容器。

### 6.4 数据库检查模块

建议第一版只做只读检查：

- 在目标 App 已退出并取得一致性副本后分析数据库；
- SQLite 主文件与 WAL / SHM 按一致性策略处理；
- 在副本上打开数据库；
- 读取 schema、表名、索引、行数和数据库完整性结果；
- 输出结构报告；
- 不修改原始数据库；
- 不尝试绕过加密或取得无权访问的密钥；
- 对无法识别或加密的数据库明确显示“无法解析”，而不是显示空聊天记录。

## 7. iOS 26 SDK 与 Liquid Glass UI 设计规范

- 注意 Reduce Transparency、Reduce Motion、动态字体和 VoiceOver；
- 不要在每个滚动单元格上叠加昂贵的模糊与动画；
- 玻璃按钮必须有明确按压反馈、禁用态和加载态。

### 7.4 设计质量要求

AI 编程助手必须先完成页面结构和设计规范，再写业务代码。不要直接生成一套默认 SwiftUI List。

所有页面应共享颜色、间距、圆角、字体、卡片、图标和动画规范。

## 8. 数据安全与隐私

微信数据属于高度敏感的个人信息。安全设计不能放到最后补。

- 默认所有备份只保存在本机；
- 不默认上传云端；
- 备份文件应支持用户主动删除；
- 备份文件可评估使用系统 Keychain 管理的本地加密密钥进行加密；
- 日志禁止记录聊天正文、账号密码、密钥、令牌和完整个人隐私内容；
- 文件清单默认只展示必要元数据；
- 导出前显示文件数量和总容量；
- 删除备份前二次确认；
- 迁移前明确告知目标数据可能被覆盖；
- 不在后台自动修改微信数据；
- 所有写入操作必须由用户明确发起；
- 对失败任务保留恢复材料。

## 9. 性能与稳定性

- 大文件采用分块复制和流式哈希，不要一次性读入内存；
- UI 与文件操作分离，耗时任务不得阻塞主线程；
- 支持取消，但取消必须在安全边界停止；
- 复制期间检查磁盘剩余空间；
- 备份和恢复都需要进度；
- 文件数量很多时使用分页或增量展示；
- 使用稳定的文件句柄和一致性检查；
- 对源文件在操作期间发生变化的情况中止或重新备份；
- 不自动清理旧备份；
- App 被系统终止后，重新启动能够恢复任务状态并给出安全提示。

## 14. 已确认的产品决策

以下两项是本项目当前确定的需求，后续 AI 编程助手不得擅自改成固定目录或默认覆盖：

1. **目录范围：用户自选目录。** 用户可在来源微信的可访问目录树中选择 Documents、Library 或其内部子目录，并逐项确认目标目录映射。不能强制只迁移 Documents + Library，也不能默认迁移整个沙盒。
2. **目标数据处理：每次迁移前询问。** 每次迁移都要列出将被替换的目标目录，并询问用户是否备份。为保证可恢复性，只有目标备份成功且校验通过后才允许覆盖；用户取消或备份失败则取消本次迁移。

注意：用户自选目录是“选择迁移范围”，不是允许任意路径写入。工具必须限制在已授权的来源与目标容器范围内，并校验相对路径、权限和映射关系。

## 15. 最终产品验收标准

产品不能仅凭“能打开文件管理器”就算完成。

正式迁移功能至少要满足：

- 能正确区分来源和目标微信实例；
- Bundle ID 与应用名称展示准确；
- 能生成完整且可校验的备份；
- 能识别不支持的数据库和资源；
- 能在迁移前解释风险；
- 目标现有数据有恢复点；
- 迁移后文件完整性检查通过；
- 失败能安全回滚；
- 用户能查看每一步日志；
- 至少有真实设备、真实测试数据的成功迁移记录；
- 对未验证的版本组合明确显示不支持。

**最终产品愿景：让用户在同一台 iPhone 上，能够清晰识别多个微信实例，安全备份自己的聊天数据，并在兼容性得到验证的前提下，将可迁移的数据从一个实例转移到另一个实例。**

这份规划的第一原则是：先证明数据真的能恢复，再把“一键迁移”做得简单漂亮。
