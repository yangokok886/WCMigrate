# 新手引导与数据暂存（1.0.1 build 16）

## 新手引导

首次打开使用 Product Tour 产品导览：直接在实际页面挖空高亮来源、目标、操作方式、文件勾选、对应路径、插件配置与暂存入口，其余区域变暗。可以点击高亮的实际控件，也可以点击引导卡片中的绿色「下一步」按钮，两种方式执行相同的演示步骤。最后一步显示「完成导览」。支持随时退出和设置中重新演练。底部四个独立入口为迁移、插件配置、数据暂存和设置。

导览仅将选择写入 ProductTour 局部状态，不写入 AppStore 的来源、目标、路径或映射。示例应用与目录固定生成；迁移检查、配置备份/导入、暂存开始按钮在导览中仅推进步骤，不调用真实文件服务。完成或退出记录 `hasCompletedProductTourV2`，清空演示状态并返回迁移页。导览中的配置入口仅介绍实际按钮，不打开文件选择器。

暂存选择应用与迁移选择应用复用 AppInstance.prioritized，官方微信、com.tencent.qy.xin、其他腾讯应用优先。

## 单微信重装流程

1. 不删除旧微信，先退出旧微信后台。WCMigrate 保持前台。
2. 底部“数据暂存” → 暂存一个应用的数据，选择原微信。
3. 默认选择 `Documents` 和 `Library`，也可指定其他相对路径。按实际数据位置选择；不会自动扩展到钥匙串、App Group 或其他容器。
4. 确认移动并开始。每个所选路径移入 `Documents/数据暂存/<UUID>/payload/<原相对路径>`。记录元信息位于同级 `record.json`，操作恢复计划位于 Application Support 的 MigrationTasks。
5. 只有暂存记录显示“已暂存”，并确认所需内容全部选中，才处理旧微信。中断状态不可当作完整暂存。中断后不要打开/改动原微信，先从记录继续。
6. 安装新微信，在暂存详情选择新的目标应用。目标必须退出，WCMigrate 继续保持前台。
7. 按原路径迁回：与目标现有路径原子互换，目标缺少路径则排他移动。目标原有内容会留在暂存目录，不做额外整份副本。完成后记录为“已迁回”，不能把留下的新微信原数据误当旧记录再次一键恢复。
8. 打开目标微信核对。文件校验不是微信数据库兼容性保证。

暂存不是虚构一个已安装应用，也不是替换 WCMigrate 的活动 Documents/Library。列表中的独立暂存记录只对应普通文件夹。保留 WCMigrate，否则其中的数据也会随卸载删除。

## 工程约束

- 复用 DirectMigrationService 的同卷 rename/exchange、排他移动和持久化恢复计划；每条映射原子，整个多路径任务不具有全事务回滚。
- 相同文件系统和权限是前提。跨卷/操作不支持时停止，不自动回退成复制后删除。
- 文件移动通过前后文件类型、路径结构、文件大小、inode/device 等身份核对；移动不遍历读取每个文件做整份 SHA-256，不能把身份核对宣传为完整内容哈希校验。
- 移动成功后来源所选路径消失；不对已退出的原微信重建空目录。不允许暂存来源为 WCMigrate 自身或其子目录，也不允许来源是包含自身容器的父目录。
- 导入/迁回仅操作所选相对路径，不读取、修改或搬运应用安装包。
- 入库元信息和 task UUID 先落盘，再执行任务；重启能根据 filesVerified 收据修复“任务完成、元信息还未更新”的窗口。
- 入库只允许空的目标路径，避免将外来文件换回原微信。迁回允许交换，以保留新应用同路径旧内容。
- 中断续传要求同一原任务、同一路径及未改变的内容身份；换签、重装或人为编辑造成容器变更时会诊断并停止，不能承诺任意情况下自动恢复。
- 不提供暂存记录的一键删除，避免误删唯一数据。用户可通过系统文件共享看到目录，手工改动会影响续传。
- 原版本号 1.0.1 保留，仅内部 build 增至 16；签名结构、Bundle ID 与最低部署系统未改变。

## 验证

`Tests/DataStagingTests.swift` 验证：暂存与迁回、原应用删除后迁回、目标旧内容保留、WCMigrate 活动配置不变、入库与迁回中断续传、成功收据的元信息恢复、重复/自身路径拒绝、非空入库拒绝、2 GiB 稀疏文件大小/尾部字节/inode 往返保持。

稀疏文件测试不是对 2 GiB 真实微信数据库的吞吐或应用内兼容性测试。真实 iPhone 容器访问、同卷移动权限和微信内部恢复结果均需设备验证。
