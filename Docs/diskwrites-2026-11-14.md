# 1.0.3 磁盘写入资源报告分析（2026-11-14）

## 日志能证明什么

- 类型：`bug_type=145`、`Event: disk writes`。
- 系统动作：`Action taken: none`；本报告没有记录终止进程，也没有 Exception / Termination Reason。因此不能把它直接当成闪退堆栈。
- 版本：1.0.3（27），系统：iOS 27.3。
- 约 11408 秒内产生 68.72 GB 文件写入脏页，平均 6023.67 KB/s。这不是应用日志文件大小，也不能全部归因于额外校验；复制数据、恢复日志及文件系统元数据都可能计入。
- 最后约 782 秒的采样期间，footprint 从 314.59 MB 增至 3591.58 MB。这是明显的稳定性风险，但仅凭本报告不能确定是否发生后续内存终止，也不能确定唯一的内存分配来源。

主要采样路径落在复制提交及恢复日志持久化，不是 SHA-256 热点证据。符号表范围匹配不能当成具体源码行定位，也不是分配追踪。

## 本轮调整

1. 新文件连续复制时，按目录复用已持久化的临时路径，移除每个文件末尾清空、下一文件再次写入的重复同步。覆盖已有内容前，仍保留独立的恢复日志持久化步骤。
2. 普通复制和续传比对改用固定 1 MiB 缓冲区读写，处理短写和 EINTR，避免每块重新创建 Foundation Data。
3. 扫描、复制循环和持久化操作增加局部 autorelease pool，限制长时间同步循环中的 Foundation 临时对象累积。
4. 根目录原子移动前，先持久化来源及目标根目录身份，供中断后识别已完成的原子操作。

这些调整针对已确认的重复落盘和可检查的临时对象生命周期风险。尚未取得用户设备上的 Allocations/VM Tracker 数据，不能宣布已消除全部内存增长或闪退。

## 验证

- 核心测试套件：133 项，1 项跳过，0 失败。
- 新增：同一目录 40 个新文件复用一次临时路径登记；普通复制 17 MiB + 137 字节的多块文件及空文件，逐字节比较结果。
- 现有测试覆盖迁移、合并、交换、取消、续传、暂存和配置备份。
- 本机 2001 小文件复制单次基准从约 1.67 秒变为约 0.87 秒，仅供开发回归参考；不能用于推断 iPhone 上几十 GB 或 20–50 万文件的耗时。
- 使用 iOS 26 SDK 生成的真机 arm64 IPA，最低系统仍为 17.0；签名为供重签使用的 ad-hoc 签名。
- 用户设备安装、运行及原始数据规模的长时间内存表现：未验证。

如果用户仍然退出，需要同一时间的 `XChatTransfer-*.ips`（Exception/Termination）或 `JetsamEvent-*.ips`，才能区别异常崩溃、内存终止和其他系统终止。只有本资源报告不足以判断最终退出原因。
